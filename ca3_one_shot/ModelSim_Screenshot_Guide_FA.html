راهنمای تهیه اسکرین‌شات نتایج ModelSim

اجرای تجمیعی شش باگ و دو مسیر سالم پردازنده MIPS پایپ‌لاین

یک فایل MEM · یک Run · یک جدول نتیجه در حافظه

قبل از شروع

  • فایل‌های .mem تست‌ها از قبل آماده‌اند و لازم نیست دوباره اسمبل شوند.
  • فایل data50.mem باید به‌عنوان حافظه داده اولیه پروژه باقی بماند.
  • تست‌بنچ TopPipeline_tb.v را تغییر ندهید.
  • مسیر دقیق سیگنال‌ها یا نام فایل حافظه دستور ممکن است در پروژه شما متفاوت باشد.
مهم: جدول‌های HTML جای اسکرین‌شات واقعی ModelSim را نمی‌گیرند. در تصویر باید خود محیط ModelSim/Questa و مقادیر نمایش‌داده‌شده قابل مشاهده باشد.

روش اصلی: نمایش همه باگ‌ها با یک بار اجرا

برای این روش از فایل زیر استفاده کنید:

TC_ALL_one_shot.mem
  1. فایل بالا را جای فایل حافظه دستور مورد انتظار $readmemh قرار دهید.
  2. data50.mem را به‌عنوان حافظه داده اولیه نگه دارید.
  3. پروژه را Compile و شبیه‌سازی TopPipeline_tb را از نو شروع کنید.
  4. در Transcript فقط یک بار اجرا کنید:
echo "TC_ALL_one_shot"
run 10000 ns

پس از پایان زمان، پنجره Memory را روی حالت Hexadecimal قرار دهید و محدوده زیر را باز کنید:

shadow_dmem[60:78]
توقف شبیه‌سازی در 10000 ns طبیعی است. باگ Branch عمداً در انتهای برنامه قرار گرفته و در پردازنده معیوب برنامه را تکرار می‌کند؛ این رفتار خودش یکی از شواهد باگ است.

خروجی گرفتن در قالب فایل متنی

پس از پایان اجرای 10000 ns، فایل dump_one_shot.do را کنار پروژه قرار دهید و در Transcript بنویسید:

do dump_one_shot.do

فایل one_shot_results.txt در پوشه کاری ModelSim ساخته می‌شود. این فایل شامل نتایج اصلی shadow_dmem[60:78] و Snapshot تمام رجیسترهای r0 تا r31 است.

اگر در فایل خروجی عبارت ERROR دیده شد، مسیر دو آرایه در پروژه شما متفاوت است. مسیر واقعی را از پنجره Objects بردارید و مقادیر DMEM و REGFILE در ابتدای فایل dump_one_shot.do اصلاح کنید.

روش اختیاری: اجرای تست‌های ایزوله

این بخش فقط زمانی لازم است که استاد برای هر باگ مدرک مستقل بخواهد یا بخواهید یک نتیجه خاص را جداگانه بررسی کنید.

  1. فایل .mem تست موردنظر، برای مثال TC02_imm_zero_ext.mem، را جای فایل حافظه دستور فعلی پروژه قرار دهید. نام فایل مقصد را از دستور $readmemh در تست‌بنچ یا ماژول حافظه دستور پیدا کنید.
  2. در ModelSim پروژه را Compile کنید. اگر پروژه از قبل تنظیم شده است، معمولاً گزینه Compile All کافی است.
  3. شبیه‌سازی TopPipeline_tb را اجرا کنید.
  4. در پنجره Transcript ابتدا نام تست و سپس زمان اجرا را وارد کنید:
echo "TC02_imm_zero_ext"
run 1500 ns

اجرای مجدد پس از تعویض فایل حافظه

ابتدا این فرمان را امتحان کنید:

restart -f
run 1500 ns

اگر فایل .mem جدید دوباره بارگذاری نشد، شبیه‌سازی را کامل ببندید و از نو اجرا کنید:

quit -sim
vsim work.TopPipeline_tb
run 1500 ns
برای TC06 زمان 1500 ns باید در تصویر مشخص باشد، چون مقدار مشاهده‌شده r27 = 0x0000000e به زمان توقف شبیه‌سازی وابسته است.

نمایش رجیسترها و حافظه در ModelSim

  1. از پنجره‌های Objects یا Memory List آرایه‌های زیر را پیدا کنید:
shadow_registerFile
shadow_dmem

اگر مسیر دقیق آن‌ها مشخص نیست، در Transcript این فرمان‌ها را امتحان کنید:

find signals -recursive *shadow_registerFile*
find signals -recursive *shadow_dmem*
  1. روی آرایه موردنظر راست‌کلیک کرده و Radix را روی Hexadecimal قرار دهید.
  2. برای رجیسترها اندیس‌های 0 تا 31 را نمایش دهید.
  3. برای حافظه داده حداقل خانه‌های مرتبط، مخصوصاً shadow_dmem[50:53]، را نمایش دهید.
اگر تمام ۳۲ رجیستر در یک تصویر خوانا جا نمی‌شوند، دو تصویر بگیرید؛ خوانایی از فشرده‌کردن همه مقادیر در یک تصویر مهم‌تر است.

چه چیزی از هر تست در تصویر باشد؟

تست موارد اصلی برای نمایش نکته تکمیلی
TC01 تمام رجیسترهای r0 تا r31 و dmem[50:53] تست موفق؛ مقادیر باید با انتظار یکسان باشند.
TC02 r16 تا r19 مغایرت‌های اصلی در r16، r17 و r18 هستند.
TC03 r16 تا r20 نتایج نادرست دستور lui باید خوانا باشند.
TC04 r16 تا r22 شیفت‌های ثابت ناموفق و شیفت‌های متغیر موفق را کنار هم نشان دهید.
TC05 r0 و r18 تا r21 ثابت‌ماندن ظاهری r0 و اثر نادرست بای‌پس روی رجیسترهای مقصد مهم است.
TC06 r17، r27 و در صورت امکان PC زمان دقیق 1500 ns حتماً در تصویر باشد.
TC07 r17 تا r22 مقادیر مربوط به مسیرهای اشتباه jr و jalr نمایش داده شوند.
TC08 تمام رجیسترها و dmem[50:53] تست موفق؛ به‌خصوص dmem[50]=0x33 و dmem[51]=0x07.

قواعد گرفتن اسکرین‌شات خوانا

  • پنجره ModelSim/Questa را Maximize کنید.
  • نام تست یا فایل .mem در Transcript دیده شود.
  • زمان پایان شبیه‌سازی مشخص باشد.
  • شماره رجیستر یا آدرس حافظه از مقدار آن قابل تشخیص باشد.
  • Radix روی Hexadecimal باشد.
  • متن‌ها بدون زوم‌کردن شدید قابل خواندن باشند.
  • اعلان‌ها، پیام‌ها و اطلاعات شخصی نامرتبط از کادر تصویر حذف شوند.
  • قبل از بستن ModelSim، تصویر ذخیره‌شده را یک بار باز و بررسی کنید.

نام‌گذاری و قرار دادن تصاویر در ZIP

یک پوشه با نام ModelSim_Screenshots کنار گزارش بسازید و تصاویر را منظم نام‌گذاری کنید:

ModelSim_Screenshots/ MS_TC01_registers.png MS_TC01_dmem.png MS_TC02_registers.png MS_TC03_registers.png MS_TC04_registers.png MS_TC05_registers.png MS_TC06_registers_pc.png MS_TC07_registers.png MS_TC08_registers.png MS_TC08_dmem.png
در ZIP نهایی باید هم فایل‌های تصویر وجود داشته باشند و هم تصاویر داخل گزارش HTML نمایش داده شوند. بعد از ساخت ZIP، آن را در یک پوشه دیگر Extract کنید و گزارش را باز کنید تا مطمئن شوید هیچ تصویر شکسته‌ای وجود ندارد.

چک نهایی قبل از ارسال

  • فایل TC_ALL_one_shot.mem با یک Run تا 10000 ns اجرا شده است.
  • مقادیر shadow_dmem[60:78] با جدول نتیجه تطبیق داده شده‌اند.
  • در صورت الزام استاد، تست‌های ایزوله نیز جداگانه اجرا شده‌اند.
  • برای تست‌های موفق، رجیسترها و حافظه مرتبط ثبت شده‌اند.
  • برای تست‌های ناموفق، رجیسترهای مغایر واضح و خوانا هستند.
  • تصویر TC06 زمان 1500 ns را نشان می‌دهد.
  • همه تصاویر PNG هستند و نام منظم دارند.
  • تصاویر داخل گزارش و بعد از Extract کردن ZIP نیز باز می‌شوند.
  • فایل ZIP نهایی شامل گزارش، پوشه Tests و پوشه تصاویر است.
